# 2. Головний принцип дизайну

Сайт має мати два окремі візуальні напрямки в межах однієї дизайн-системи.

## 2.1. Магазин — Light Commerce

Основний напрямок для:
- Головної сторінки.
- Каталогу.
- Категорій товарів.
- Сторінок окремих товарів.
- Пошуку та фільтрів.
- Кошика.
- Сторінок оформлення замовлення.

### Характер дизайну

Світлий, чистий, мінімалістичний та преміальний інтерфейс.

Основна увага приділяється товарам, фотографіям, цінам та характеристикам.

Використовувати:
- Молочний та білий фон.
- Темні заголовки.
- Теплі бежеві відтінки.
- Помаранчеві акценти.
- Якісні фотографії камінів.
- Чітку типографіку.
- Достатню кількість вільного простору.

### Візуальна атмосфера

Каталог повинен нагадувати преміальний магазин товарів для інтер'єру, а не технічний склад обладнання.

Товари повинні бути головним елементом сторінки.

Не перевантажувати картки декоративними елементами, зайвими рамками та непотрібною інформацією.

## 2.2. Монтаж — Dark Service Experience

Основний напрямок для:
- Сторінки послуги монтажу.
- Сторінки монтажу камінів.
- Сторінки монтажу димоходів.
- Галереї виконаних робіт.
- Етапів роботи.
- Переваг компанії.
- Гарантій.
- Форм замовлення монтажу.

### Характер дизайну

Темний, атмосферний, сучасний та професійний інтерфейс.

Основна увага приділяється:
- Реальним фотографіям монтажу.
- Майстрам та процесу роботи.
- Готовим проєктам.
- Безпеці встановлення.
- Професіоналізму.
- Гарантіям.
- Залученню клієнтів.

Використовувати:
- Графітовий фон.
- Темні фотографії інтер'єрів.
- Контрастний білий текст.
- Помаранчеві акценти.
- Великі фотографії виконаних робіт.
- Виразні заголовки.
- Чіткі CTA-кнопки.

### Візуальна атмосфера

Сторінка монтажу повинна створювати відчуття професійної компанії з досвідом виконання робіт.

Не робити її схожою на будівельний сайт із типовими шаблонними блоками.

Використовувати реальні фотографії робіт, якщо вони доступні.

Не вигадувати досвід, кількість виконаних проєктів, сертифікати, гарантії чи відгуки.

## 2.3. Єдність бренду

Попри різний вигляд магазину та монтажу, вони повинні залишатися частинами одного бренду FireHome.

Спільними мають бути:
- Логотип.
- Типографіка.
- Навігація.
- Стиль кнопок.
- Стиль іконок.
- Відступи.
- Принципи компонування.
- Форми.
- Стани інтерактивних елементів.
- Загальна якість дизайну.

Не створювати два абсолютно незалежні дизайни.

Різниця повинна досягатися переважно через фони, фотографії, контраст та атмосферу.

## 3.2. Правила використання кольорів

Помаранчевий — головний акцент бренду.

Використовувати для:
- Основних CTA-кнопок.
- Активних станів.
- Важливих посилань.
- Індикаторів вибору.
- Невеликих графічних акцентів.
- Цінових або статусних акцентів, коли це доречно.

Не використовувати помаранчевий як основний фон великих секцій.

Не робити весь сайт помаранчевим.

Графітовий колір використовувати для:
- Сторінок монтажу.
- Темних презентаційних секцій.
- Footer.
- Контрастних інформаційних блоків.

Молочний фон використовувати як основний фон магазину.

Бежевий використовувати помірно, щоб додати теплоти та природності.

## 3.3. Заборонено

- Повністю чорно-білий дизайн.
- Використання випадкових кольорів, не передбачених палітрою.
- Надмірна кількість помаранчевого.
- Яскраві кислотні кольори.
- Випадкові градієнти.
- Кольорові фони без зрозумілої функції.
- Різні відтінки одного кольору в однакових компонентах без причини.

Для статусів успіху та помилки використовувати кольори Success та Error з палітри. Попередження можуть використовувати стандартний семантичний колір, якщо цього вимагає UX.

# 4. Типографіка

Типографіка повинна бути сучасною, читабельною та виразною.

Рекомендовані шрифти:

- Inter — основний текст інтерфейсу.
- Montserrat — заголовки та акцентні елементи.

Якщо в проєкті вже використовується якісна узгоджена типографіка, не замінювати її без необхідності.

## 4.1. Ієрархія заголовків

### H1
- Desktop: 48–64px.
- Mobile: 32–40px.
- Font weight: 600–700.
- Line height: 1.05–1.15.

### H2
- Desktop: 32–40px.
- Mobile: 26–32px.
- Font weight: 600.
- Line height: 1.15–1.25.

### H3
- Desktop: 22–28px.
- Mobile: 20–24px.
- Font weight: 600.

### Основний текст
- Desktop: 15–17px.
- Mobile: 14–16px.
- Font weight: 400.
- Line height: 1.5–1.65.

### Допоміжний текст
- 12–14px.
- Використовувати для характеристик, підписів та другорядної інформації.

Не використовувати надто дрібний текст.

Не використовувати надмірно жирні заголовки для всіх елементів.

Не робити всі тексти однакового розміру.

# 5. Layout та відступи

Дотримуватися єдиної системи відступів.

Використовувати стандартну шкалу Tailwind CSS.

Рекомендовані значення:
- 4px — мінімальні внутрішні відступи.
- 8px — компактні відступи.
- 12px — відстань між близькими елементами.
- 16px — стандартні відступи.
- 24px — відстань між компонентами.
- 32px — відстань між групами елементів.
- 48px — відстань між великими блоками.
- 64–96px — вертикальні відступи між секціями.

### Контейнер

- Максимальна ширина основного контенту: 1280px.
- На великих екранах залишати достатньо бокових відступів.
- На мобільних використовувати 16–20px бокових відступів.
- Не розтягувати текстові блоки на всю ширину екрана.

### Секції

- Кожна секція повинна мати зрозумілу структуру.
- Не створювати надто щільний інтерфейс.
- Не використовувати однакову композицію для всіх секцій.
- Чергувати фотографії, текстові блоки, картки та повноширинні секції.
- Дотримуватися логічної візуальної ієрархії.

# 6. Кнопки та інтерактивні елементи

## 6.1. Primary Button

Основна кнопка сайту.

Стиль:
- Помаранчевий фон #F56B00.
- Білий текст.
- Font weight 500–600.
- Заокруглення rounded-md.
- Висота не менше 44px (h-11).
- Достатні горизонтальні відступи.
- Плавний hover.
- Чіткий disabled state.

Використовувати для:
- Купити.
- Замовити монтаж.
- Залишити заявку.
- Надіслати форму.
- Оформити замовлення.

## 6.2. Secondary Button

- Прозорий або білий фон.
- Темний текст.
- Тонка рамка.
- Помірне заокруглення.
- Hover зі зміною фону або рамки.

Використовувати для:
- Детальніше.
- Переглянути каталог.
- Усі роботи.
- Повернутися назад.

## 6.3. Кнопки на темному фоні

На темних секціях використовувати:
- Помаранчеві Primary Button.
- Світлі контурні Secondary Button.

Кнопки повинні мати достатній контраст.

## 6.4. Поведінка кнопок

Для інтерактивних елементів обов'язково передбачати:
- Default.
- Hover.
- Focus.
- Active.
- Disabled.
- Loading, якщо виконується асинхронна операція.

Focus state: контур 2px з відступом. На світлому фоні колір контуру Graphite, на темному Accent Orange.

Не створювати кнопки, які візуально виглядають активними, але нічого не роблять.

# 7. Форми

Форми повинні бути максимально простими та зрозумілими.

Основні поля:
- Ім'я.
- Телефон.
- Повідомлення (необов'язково).

Надсилати лише поля, які підтримує API. `POST /callback-requests` приймає тільки `name` і `phone`. Інші поля не додавати, доки їх не підтримує бекенд.

Правила:
- Білі або темні поля залежно від секції.
- Чіткі labels.
- Зрозумілі placeholders.
- Помірне заокруглення.
- Висота полів не менше 44px (h-11).
- На світлому фоні межа поля Input Border.
- Помітний focus state.
- Зрозумілі повідомлення про помилки.
- Валідація.
- Loading state під час відправлення.
- Повідомлення про успішне надсилання.

Не перевантажувати форми великою кількістю полів.

Не використовувати placeholder замість label для важливих полів.

На темних секціях форми повинні залишатися контрастними та зручними.

# 8. Header та навігація

Header — спільний для всіх сторінок.

Основні елементи:
- Логотип FireHome.
- Каталог.
- Про нас.
- Монтаж.
- Доставка.
- Контакти.
- Пошук.
- Кошик.
- Контактний телефон (якщо є).

### Візуальний стиль

- Чистий та мінімалістичний.
- Світлий фон на сторінках магазину.
- На темних сторінках допустимий темний варіант.
- Зрозумілі hover-стани.
- Активний пункт навігації.
- Достатньо простору між пунктами.

Header повинен бути адаптивним.

На мобільних використовувати компактне меню.

Не дублювати однакові навігаційні елементи без потреби.

# 9. Головна сторінка

Головна сторінка повинна презентувати обидва напрямки бізнесу.

Рекомендована структура:

## 9.1. Hero

Велика атмосферна фотографія сучасного інтер'єру з каміном.

Можливий темний overlay для читабельності тексту.

Контент:
- Заголовок про каміни та затишок.
- Короткий опис компанії.
- Primary CTA: Переглянути каталог.
- Secondary CTA: Замовити монтаж.

Hero повинен одразу пояснювати, чим займається компанія.

Не використовувати випадкові стокові фотографії низької якості.

## 9.2. Категорії товарів

Світла секція.

Категорії:
- Каміни.
- Печі.
- Камінні топки.
- Біокаміни.
- Інші категорії відповідно до асортименту.

Кожна категорія:
- Якісне фото.
- Назва.
- Короткий опис за необхідності.
- Посилання на каталог.

## 9.3. Популярні товари

Світла секція з картками товарів.

Використовувати єдиний компонент ProductCard.

Показувати:
- Фото.
- Назву.
- Ціну.
- Ключові характеристики.
- Наявність, якщо відомо.
- Кнопку або посилання на товар.

## 9.4. Секція монтажу

Окремий великий темний блок.

Використовувати:
- Графітовий фон.
- Великі реальні фотографії робіт.
- Контрастний заголовок.
- Короткий опис.
- Список переваг.
- CTA «Замовити монтаж».
- Посилання на сторінку послуги.

Це один із найважливіших блоків головної сторінки.

Монтаж не повинен виглядати як додаткова послуга, про яку згадали внизу сторінки.

## 9.5. Переваги компанії

Можливі переваги:
- Допомога у виборі обладнання.
- Професійний монтаж.
- Підбір димохідних систем.
- Гарантійне обслуговування, якщо підтверджено.
- Консультації.

Не вигадувати факти про компанію.

## 9.6. Про компанію

Світла або тепла нейтральна секція.

Використовувати реальні фотографії та фактичну інформацію.

## 9.7. Відгуки

Показувати лише реальні відгуки.

Не генерувати фіктивні імена, фотографії або тексти відгуків.

## 9.8. Контакти

- Телефон.
- Email.
- Адреса, якщо є.
- Графік роботи, якщо відомий.
- Форма зворотного зв'язку.

## 9.9. Footer

Темний графітовий фон.

Містить:
- Логотип.
- Короткий опис.
- Навігацію.
- Категорії.
- Посилання на монтаж.
- Контакти.
- Соціальні мережі, якщо є.
- Політики та юридичну інформацію.

# 10. Каталог товарів

Каталог — одна з найважливіших частин сайту.

Він повинен бути максимально зручним для вибору товару.

### Візуальний напрямок

Виключно світлий інтерфейс.

Основний фон #F7F5F0 або білий.

Картки товарів — білі.

Текст — графітовий.

Акценти — помаранчеві.

### Структура каталогу

- Breadcrumbs.
- Назва категорії.
- Короткий опис.
- Фільтри.
- Сортування.
- Кількість знайдених товарів, якщо доступно.
- Сітка товарів.
- Пагінація або інший механізм завантаження.

### Фільтри

Фільтри повинні відповідати реальним характеристикам товарів.

Можливі параметри:
- Ціна.
- Виробник.
- Тип обладнання.
- Потужність.
- Матеріал.
- Тип палива.
- Наявність.

Не створювати фільтри, які не підтримуються даними каталогу.

На Desktop фільтри можуть бути в лівій колонці.

На Mobile фільтри відкривати в окремій панелі або drawer.

### Сортування

Передбачити:
- За популярністю, якщо є відповідні дані.
- Від дешевих до дорогих.
- Від дорогих до дешевих.
- За новизною, якщо є дата додавання.

Не показувати фіктивну популярність.

---

# 11. Картка товару — ProductCard

Картки товарів повинні бути візуально однаковими в межах каталогу.

### Структура

1. Фото товару.
2. Назва.
3. Короткі характеристики.
4. Ціна.
5. Наявність, якщо відома.
6. CTA або посилання на деталі.

### Візуальні правила

- Білий фон.
- Якісне фото.
- Акуратне компонування.
- Чітка типографіка.
- Помаранчеві акценти.
- Помірне заокруглення.
- Легка зміна тіні або рамки при hover.

Фото повинно займати достатню площу.

Не обрізати важливі частини товару.

Не використовувати різні пропорції фотографій у картках одного каталогу.

### Заборонено

- Перевантажувати картку характеристиками.
- Використовувати багато різних бейджів.
- Додавати декоративні іконки без функції.
- Робити кожну картку візуально іншою.

---

# 12. Сторінка товару

Сторінка товару повинна допомагати клієнту прийняти рішення про покупку.

Dark Service Experience.

Велика галерея реальних проєктів.

Під час створення нових компонентів обов'язково враховувати мобільну версію.

На мобільних:
- Не допускати горизонтального скролу.
- Заголовки повинні правильно переноситися.
- Кнопки повинні бути зручними для натискання.
- Фотографії повинні коректно обрізатися.
- Каталог повинен переходити на 1–2 колонки.
- Фільтри повинні відкриватися в зручному форматі.
- Форми повинні займати доступну ширину.
- Навігація повинна бути компактною.

Не просто зменшувати Desktop-дизайн.

Мобільний інтерфейс повинен мати власну логіку компонування.

8. Не приховувати важливу інформацію.
9. Не створювати зайвих кроків до замовлення.
10. Не використовувати маніпулятивні елементи.

# 21. Технічні правила стилізації

Проєкт використовує Tailwind CSS.

Основні правила:
- Використовувати Tailwind-класи безпосередньо в JSX.
- Дотримуватися єдиної кольорової палітри.
- Повторювані складні стилі виносити в повторно використовувані компоненти.
- Не створювати зайвий кастомний CSS.
- Не встановлювати UI-бібліотеки без реальної необхідності.
- Не використовувати випадкові значення кольорів.
- Не дублювати класи без потреби.

Для кольорів використовувати узгоджені дизайн-токени.

Проєкт використовує Tailwind CSS v4, файлу `tailwind.config` немає. Кольори визначені як токени в `@theme` у `app/globals.css`. Не дублювати HEX у компонентах.

Не змінювати `@theme` без перевірки поточної версії та структури проєкту.

Перед створенням нового компонента перевіряти, чи вже існує аналогічний.

# 24. Правила роботи Claude Code з дизайном

Перед початком роботи над новою сторінкою або компонентом:

1. Переглянути поточну структуру проєкту.
2. Перевірити наявні компоненти.
3. Перевірити існуючі дизайн-рішення.
4. Зрозуміти, до якого напрямку належить сторінка: Light Commerce чи Dark Service Experience.
5. Використовувати наявну дизайн-систему.
6. Не створювати нові кольори та стилі без причини.
7. Перевірити адаптивність.
8. Перевірити всі інтерактивні стани.

### Якщо завдання стосується магазину

Використовувати Light Commerce.

Не робити каталог темним лише тому, що сторінка монтажу має темний дизайн.

### Якщо завдання стосується монтажу

Використовувати Dark Service Experience.

Не перетворювати сторінку монтажу на звичайну світлу сторінку каталогу.

### Якщо завдання стосується спільних компонентів

Зберігати єдину дизайн-систему та передбачати потрібні варіанти оформлення.

### Під час редизайну

- Не змінювати бізнес-логіку без потреби.
- Не видаляти існуючий функціонал.
- Не вигадувати дані.
- Не ламати API.
- Не змінювати структуру бази даних заради візуальних змін.
- Не встановлювати нові залежності без необхідності.

Вони мають різний візуальний характер, але є частинами одного впізнаваного бренду.

Усі нові сторінки та компоненти повинні відповідати цим принципам.
